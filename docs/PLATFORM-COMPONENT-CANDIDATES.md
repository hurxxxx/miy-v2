# 플랫폼 공통 컴포넌트 후보

이 후보들은 [범용 기능 계획](COMMON-FEATURES-PLAN.md#m7m11-공식-업무-앱)의 M10(대용량 전송과 드라이브)에서 함께 인수한다(미구현).

출발점은 [조직용 앱 사용자 검증](releases/user-test-20261121-131334/report.md)이다. 인증된 `miy component list`에는 공용 UI `ui` 1.0.0, 1.0.1, 1.1.0이 표시됐다. `ui` 1.1.0의 카탈로그 설명에는 작은 첨부파일과 디렉터리 선택·공유가 포함된다. 두 프로젝트의 `miy component sync`에서도 1.1.0을 받았다. 파일 전송과 파일 저장소는 독립 컴포넌트로 표시되지 않았다. 사용자에게 배포된 계약에는 SDK의 제한형 파일 저장소와 10 MiB 파일 전송, 릴리스별 권한 승인, 앱의 자료 ACL 확인이 문서화되어 있다. Claude Code가 만든 파일 앱은 이 저장소를 호출하고 화면·메타데이터 연결·공유 흐름을 앱에서 구현했다. 초판에서는 상대 경로 계약을 잘못 적용해 전송에서 404가 났다. 수정한 릴리스는 개발·운영에서 합성 파일 업로드와 원본이 일치하는 다운로드를 통과했다.

| 후보 | 살필 사용자 흐름 | 공통화 및 인수 기준 |
|---|---|---|
| 파일 업로드·다운로드 UI | 개인·공용 영역에서 파일을 선택하고 전송 상태를 확인한 뒤 파일을 내려받는다. | 파일 선택, 진행·실패 표시, 재시도를 앱에서 연결할 수 있는 UI인지 확인한다. 업로드가 실패했을 때 원인을 알 수 있고, 실패한 파일을 다시 전송할 수 있어야 한다. 다운로드한 파일은 원본과 일치해야 한다. |
| 파일 저장소 | 개인·공용 파일의 메타데이터를 목록에서 보고, 권한에 따라 열거나 삭제한다. | 파일과 메타데이터의 보관, 소유자와 조직 범위, 목록·다운로드·삭제의 서버 권한 검사를 살핀다. 타인의 개인 파일은 앱이 제공한 직접 링크로도 열 수 없어야 하고, 공용 권한을 회수한 사용자의 접근도 차단돼야 한다. |

공용 파일의 대상 선택도 재사용 후보다. 파일 앱은 원시 조직 UUID를 입력받아 관리 콘솔 감사 기록을 찾아야 했고, 노트 앱은 같은 조직을 표시 이름으로 선택했다. 기존 디렉터리 선택 UI와 파일 전송 UI를 결합해 두 앱에서 이름 기반 선택과 실제 접근 권한이 일치하는지 검토한다. 노트 앱 첨부는 파일 앱에서 재사용 경로를 확인한 뒤 검증할 후보다.
