# 플랫폼 영역과 후속 UI 계약

- 기준: [사내 앱 실행·관리 경계](../../APP-BOUNDARIES.md)와 [앱 프레임 설계](../../APP-FRAMES.md). **업무 앱의 설치별 출처 프레임 실행·prod/dev/console 세 출처 분리 구현과 운영 반영 완료**(서버·UI·프레임 런타임 `7defdb0`, schema 22, [11-12 리뷰 보완 배포](../../releases/app-frames-review-fixes-2026-11-12-deployment.json)).
- UI-1~5의 ai-do 기반 이식·후속 리뷰는 [완료 이력](../UIUX-MIGRATION-UI1-5.md)에 보존한다. 후속 원본은 miy v1이다. v1 코드를 그대로 이식하지 않고, 업무 앱은 2026-11-10 채택한 v2 프레임 계약으로 실행한다.

## 세 영역의 화면 책임

| 영역 | 화면 계약 |
| --- | --- |
| 업무 포털·dev 포털 | 업무 포털은 prod 목록·앱, dev 포털은 권한 있는 사용자의 dev 미리보기·시험 앱을 제공. 각 포털 안에서 통합 라우팅하며 기술 상태·DB·이미지·관리 작업은 콘솔에서 제공 |
| 앱 관리 콘솔 | 담당 앱·환경, 미설치/사용 중지 앱, 릴리스·작업·진단과 개인 CLI 승인. 서버가 제공한 동작별 권한 사용 |
| 플랫폼 관리 | 같은 콘솔 안의 사용자·그룹·권한·등록·설치 승인·감사·공용 자산. Keycloak 로그인은 콘솔 `/identity`에서 제공 |

플랫폼 화면은 같은 페이지에 두고 업무 앱 화면만 설치별 출처 iframe에서 실행한다. 독립 빌드한 MF/AppRoot 모듈은 프레임 런타임이 읽으며 포털 라우터는 주소와 탐색을 브리지로 연결한다. 현재 운영 프로필은 같은 사이트의 설치별 호스트(P2)이며 외부 앱 수용을 위한 별도 사이트(P1) 인수는 남아 있다. prod 포털·dev 포털·관리/CLI 승인/로그인 콘솔은 별도 출처다. IdP는 콘솔에 함께 두고 콘솔에는 앱 모듈·활성 앱 콘텐츠를 제공하지 않는다. 테마·언어·탐색·입력 유실·선택기는 SDK·프레임 런타임·공용 UI의 담당 기능에서 확장한다. API는 화면 브리지로 대행하지 않고 앱 출처의 인증 경로를 사용한다. 상세 세션 용도와 권한은 [경계 설계](../../APP-BOUNDARIES.md#앱-실행-계약)와 [코어 권한](../../CORE-PERMISSIONS.md)을 따른다.

단일 IP·사설 CA HTTPS를 지원하고 출처별 호스트명을 권장한다. 세 출처의 포트를 나눌 수 있지만 쿠키 격리로 간주하지 않는다. 관리자·develop 계정도 권한에 맞게 dev 포털에서 앱을 확인한다. prod 업무 입장은 명시적 use/all과 앱 ACL을 따른다. 개발 단계에서는 구 UI·SDK·CLI 호환을 위해 전환 계층을 추가하지 않아도 된다.

**다른 출처로 가는 링크만 새 탭으로 연다.** 포털↔콘솔·prod↔dev 포털 이동, 콘솔의 "포털에서 앱 열기"·앱 경로 안내, 포털의 관리 콘솔·개인 CLI 연결이 해당한다. 포털 안에서 앱을 여는 홈의 앱 열기와 앱 레일은 통합 라우팅을 위해 같은 탭을 유지한다. 2026-11-09 [사용자 결정과 격리 검증](../../releases/boundary-followup-2026-11-09-validation.json)으로 이 동작을 확정했고, 현재 세 출처 UI는 [dev 포털 배포](../../releases/dev-portal-2026-11-09-deployment.json)에 반영했다. `↗` 표시와 접근성 안내, `noopener noreferrer`를 사용한다. 새 탭 링크는 원래 화면을 떠나지 않으므로 입력 유실 확인을 띄우지 않는다. 각 영역 내부 메뉴·앱 내부 라우팅·로그인/로그아웃·기존 주소의 자동 이동은 같은 탭을 유지한다.

## 7. 기본 UI 이후 후속 작업의 경계

기존 참조 번호는 유지한다. 아래의 순서는 [추진 계획](../../PLAN.md#다음-우선-작업)이 정한다.

- **7-1 공용 UI:** v1 UI 원칙·primitive·날짜/공휴일(V1-U1·U4·U5)의 독립 부분은 병행할 수 있다. 테마/언어·SDK 확장(U2·U3·U6)은 구현된 AppRuntime·프레임 런타임·브리지 v1에 맞춘다. 현재 라이트 테마와 테마 메시지 계약을 다크/시스템 테마·다국어 기능 완료로 해석하지 않는다. 실제 구현 순서는 PLAN을 따르고 게시 SDK·컴포넌트는 새 불변 버전으로 확장한다.
- **7-2 권한 기반:** 최소 보안 보완 다음에 공통 디렉터리·현재 그룹 확인과 앱 소유 ACL의 공통 SDK·회수·감사 계약을 구현한다. 전역 워크스페이스를 만들지 않는다. PLM 등 독립 업무 앱은 이 공통 기능을 사용하며 서비스 계정·API Invoke·업무 이벤트·대용량 파일은 PLAN의 후속 순서로 진행한다. 전체 PLM 기능을 현재 보안 단계의 완료 조건으로 두지 않는다.
- **7-3 공통 업무 기능:** Storage·파일·알림·편집기·선택 업무 앱. 경계 정리를 대규모 디자인 개편이나 v1 코드 복사의 근거로 삼지 않는다.

## 검증과 상태

동적 앱 추가·통합 라우팅의 인수 요구를 유지한다. 세 출처와 세션 용도·환경별 앱 입장, 콘솔의 device CLI 승인·IdP, 관리/사용 권한, 응답·문자열 방어를 확인한 이전 [dev 포털 격리 검증](../../releases/dev-portal-2026-11-09-validation.json)과 [콘솔 이동 기록](../../releases/console-hostname-2026-11-09-deployment.json)은 당시 범위로 보존한다. 프레임의 실행·인증·입력 보호·브라우저별 UX는 [프레임 인수](../../APP-FRAMES.md#6-실증-계획)와 [리뷰 보완 검증](../../releases/app-frames-review-fixes-2026-11-12-validation.json)을 따른다. 11-12 [배포 후 확인](../../releases/app-frames-review-fixes-2026-11-12-deployment.json)에서는 실제 로그인 후 prod 앱 2개·dev 앱 2개를 서로 다른 설치 출처에서 읽기 전용으로 열었다. 이는 전체 업무 인수가 아니다. 실제 Windows·기존 기기 worker 정리·운영 인쇄 전체 인수, P2 쿠키 간섭과 화면낭독 출력 확인은 NOT_RUN이다. 앱별 문서·출처 분리와 P2·P3의 쿠키·사이트 격리 한계는 구분한다. 과거 PASS를 새 인수로 옮기지 않으며 운영 dist·Windows 사용자 수행 원칙을 유지한다.
