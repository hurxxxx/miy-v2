## 다음 우선 작업

**이 표가 작업 순서의 유일한 기준이다.** 세부 기준은 [UI 이식](UIUX-MIGRATION.md), [코어 안정화](CORE-HARDENING.md), [v1 적용 ID](V1-ADOPTION.md)를 따른다. 보안은 [사내 최소 설계](APP-BOUNDARIES.md)로 좁힌다. 업무 앱은 설치별 출처 iframe([앱 프레임 설계](APP-FRAMES.md)), 플랫폼 화면은 통합 라우팅, 단일 IP HTTPS를 유지하고 prod 포털·dev 포털·관리/로그인 콘솔 세 출처를 사용한다. 외부 앱 격리·별도 IdP·자동 CA는 선행 조건이 아니며 개발 단계의 API·CLI·설정 하위 호환을 강제하지 않는다. 공통 인증·권한 도구는 플랫폼, 업무 데이터·선택적 공간·ACL은 앱 소유다. PLM 등 독립 앱의 후속 요구는 [PRD](PRD.md)와 [공통 업무 권한](CORE-PERMISSIONS.md#공통-업무-권한과-앱-연계)을 따른다.

앞선 리뷰를 반영해 **변경 범위의 최소 백업·복원 확인과 디스크·DB 보호를 먼저 확보하되, 전체 백업 제품·호스트 updater 완성을 기능 개발의 선행 조건으로 두지 않는다.** 전체 코어 3~5차의 남은 구현과 종합 인수는 베타 전 단계에서 완료한다. 이미 수행한 ai-do 기반 기본 UI의 구현·검증 이력은 보존한다.

**2026-11-05 결정: 2의 남은 기능을 더 쌓기 전에 "기반"(코어 구조 다지기)을 먼저 한다.** 같은 날 후속 리뷰의 결함(위임 실행 접수 후 403, 작업 목록·상세 권한 불일치, main CI 실패 중 운영 반영)이 흩어진 권한 판정, 세 곳에서 따로 쓰는 API 형식, 수동으로만 도는 DB 회귀에서 나왔다. 서비스 계정(A2)·디렉터리 선택기(G4)·공용 UI(3)는 이 구조 위에 올린다. 표의 번호는 다른 문서가 참조하므로 바꾸지 않는다.

2026-11-06 리뷰의 권한 스냅샷·위임 잠금 순서·CLI 모의 응답·API 검사 보완은 [구조 기반 보완 기록](releases/core-foundation-review-2026-11-06-validation.json)에 있다. 일반 `core-rollout.py`의 대상 SHA 필수 CI gate는 [2026-11-09 후속 검증](releases/boundary-followup-2026-11-09-validation.json)을 거쳐 구현·배포에 사용했다. migration/설정 전환의 일반화와 전체 호스트 updater는 후속이다.

**현재 개발 순서: 운영 반영 기록 동기화 → 번들 0.9.0 CLI 게시(아래 '격리' 행, 업무 앱 프레임은 2026-11-12 운영 반영, G4 서버 부분은 병행) → G4·G5·G6 및 기존 기능.** 경계의 구현·격리 필수 인수와 이번 운영 전환은 완료했으며 아래 BV 잔여 항목은 계속 추적한다. 독립 UI 자산·기존 AppRuntime 기능은 호환 검사를 하며 병행할 수 있다. 공개 운영의 긴급 대응과 모든 후속 권장 인수를 사내 기능 개발의 공통 선행 조건으로 묶지 않는다.

### 결정이 필요한 사항

선택지와 권고는 [v1 적용 계획 §5](V1-ADOPTION.md#5-결정이-필요한-사항)에 있다.

1. 첫 업무 앱: **결정(2026-11-03): 프로젝트·업무 앱**(3번의 대표 앱과 같음). 최소 보호는 순서 2가 바꾸는 core DB 범위로 구현했고([운영 안내 §6](SERVER-OPERATIONS.md#6-변경-전-최소-백업과-복원-확인)), 앱 DB·파일은 해당 기능이 생길 때 같은 방식으로 넓힌다. 전체 호스트 updater는 기능 개발의 선행 조건으로 두지 않는다.
2. 그룹 정본·동기화: **결정(2026-11-03): 코어 DB가 그룹·주 소속·수동 멤버의 정본이고 Keycloak은 인증만 맡는다.** v1의 단일 그룹·주 소속 정확 일치·수동 사용자 배정을 따르고, 하위 부서 자동 권한 상속·중첩 그룹은 제외한다. 인사 연동은 출처·동기화·회수 계약을 정의한 뒤 코어 DB에 쓰는 커넥터로 추가한다. 그룹으로 줄 수 있는 앱 권한은 `use`·`develop`이며, 운영 배포(`deploy`)는 배포 승인·특권 그룹 보호를 갖출 때까지 사람별로만 준다.
3. 대표 앱의 내부 공간·역할·공유·회수 계약: **결정(2026-11-03): v1 PMS 공간 모델을 줄인 프로젝트·업무 앱**에서 구현·인수한다. 플랫폼 공통 워크스페이스는 도입하지 않으며 공간이 필요 없는 앱은 그대로 동작한다. 2026-11-06 PLM 검토는 이 대표 앱을 대체하지 않고 공통 ACL과 작은 PLM→PDM/MES 연계 인수를 추가하는 요구다. 업무 앱 구현은 코어와 분리한다.
4. 대외 소개 자료의 제품 요구(V1-R1~R5, 비용 집계 V1-A3는 R2에 포함)와 v1 보류 앱(Mail·Community·Whiteboard·Video-chat)의 채택 범위. 상세 범위는 v1 적용 계획 §3.6·3.8에서 관리한다.
5. Hermes 채택 유지: PRD 합의 사항이다. 다만 v1은 upstream 공백 9건을 자체 어댑터로 메웠고, 그중 일부는 비공개 API를 썼다. 4-1 실험에서 이 비용을 확인한다.
6. **확정(2026-11-09): 사내 최소 보안·개발 편의 우선.** 회사가 관리하는 앱·개발자와 제한된 사내 접속을 대상으로 AppRoot·단일 IP HTTPS를 유지한다(업무 앱 실행은 7). prod 포털·dev 포털·콘솔+Keycloak 세 출처, portal/dev_portal/console 세션·환경 제한·콘솔 device 승인·prod 사용/관리 분리가 현재 기준이다. legacy 로그인은 종료했고 현재 게시 CLI·SDK는 유지했다. 개발 단계의 구 API·CLI·설정 호환은 강제하지 않는다. 같은 포털 앱 격리와 포트 쿠키 격리를 주장하지 않는다. 별도 IdP·MFA 의무화·자동 CA·전체 앱 전환은 선행 조건이 아니며 공개 서버를 사내 범위로 자동 인정하지 않는다. 상세는 [APP-BOUNDARIES](APP-BOUNDARIES.md). 미지원 service/AI credential·업무 WebSocket은 기본 거부다.

7. **결정(2026-11-09 검토, 2026-11-10 채택): 업무 앱 iframe 실행.** 같은 포털 앱 코드가 연결 승인 없이 다른 앱 API를 호출하는 한계와 외부·AI 생성 앱 수용 목표 때문에, 업무 앱만 설치별 출처 iframe에서 실행하는 혼합 구조를 [앱 프레임 설계](APP-FRAMES.md)로 실증했고 2026-11-10 사용자가 채택했다(D1). 업무 앱 실행은 6의 MF 대신 이 설계를 따르며, 2026-11-12 운영에 반영했다.

현재 v2의 실제 데이터에 영향을 주는 변경 전에는 해당 범위의 백업·복구 경로를 먼저 확보한다. 권한 계약·기존 설치 전환은 [코어 권한 안내](CORE-PERMISSIONS.md)를 따른다. 기본 회귀 검사는 각 단계에서 수행한다. 다른 단계의 PASS를 이월하지 않는다.

### 미해결 호환성 관찰

Docker 28 classic image store의 native `docker save` 결과는 image `.Id`가 가리키는 config digest와 OCI manifest digest가 달라 현재 native export 검사에 실패한다. 이번 CI에서 확인한 호환성 과제이며 제품의 digest 검증을 완화하거나 해결 PASS로 표시하지 않았다. 운영과 격리 회귀 112개는 containerd image store 범위다. 생성한 classic archive를 이 기준 저장소로 import한 시험은 모든 Docker 저장소의 raw native export 지원을 뜻하지 않는다. 상세 범위는 [회귀 실행 환경과 한계](../scripts/runtime-regression/README.md)를 따른다.

### 보류 중인 사용성 개선

0.6.3 사용자 테스트와 독립 AI 인수에서 나온 항목이다. 이전 `docs/TODO.md`에서 옮겼다. 해당 화면을 고칠 때 함께 처리한다.

- `get_contract` 응답이 Claude 클라이언트 한도를 넘는다(119,525자). 짧은 개요와 섹션별 조회 경로를 추가하고, 파일로 저장될 때 경로와 읽는 방법을 안내한다.
- 게시 0.7.0의 HTTP IP 접속에서는 클립보드 API가 제한될 수 있다. 설치 명령을 직접 선택·복사하는 안내와 복사 상태 표시를 개선한다.
- 설치 안내에서 기존 활성 연결과 이번 명령의 대상 서버가 다르면 두 주소와 추가·선택 명령을 쉽게 비교하도록 배치한다. context 이름 `default`를 미리 정해진 서버로 오해하지 않게 한다.
- 개발 세션이 충돌하거나 만료됐을 때 세션 소유자, 남은 시간, 중지 후 재실행 절차를 보여 준다.
- 개발자 등록 요청, 관리자 승인, 운영 배포 권한 부여의 진행 상태를 이어서 보여 준다.
- 배포 작업이 앱 상태 확인 뒤 후처리에서 실패할 수 있다. 실제 앱 상태와 실패 위치를 구분해 표시하고, job ID로 진단 기록을 찾도록 안내한다.
- 실제 IdP의 로그인 만료·중복 콜백 재현과 복구 화면 인수가 남아 있다. 2026-10-28 사용자 테스트에서 Keycloak `expired_code`·`already_logged_in`이 관찰됐다(요청 ID `00cb6859-9481-47ac-8341-78b653627a96`).
- Windows 설치 파일의 코드 서명과 조직별 배포 정책 적용은 후속으로 검토한다.

## 문서의 역할

문서별 담당 범위와 보관 문서는 [문서 지도](README.md)가 관리한다. 요구사항을 바꿀 때에는 PRD를 먼저 갱신하고 관련 계획과 검토 문서를 연결한다. 외부 프로젝트와 v1의 기능 설명은 miy에 적용할 설계 제안과 구분한다.
