# miy 추진 계획

- 작성일: 2026-10-20 · 정리일: 2026-11-23
- 기준: 소스 구현·격리 검증·게시·개발 서버 반영을 구분한다. 호스트별 소스·버전·복구 경로는 [서버 운영 안내](SERVER-OPERATIONS.md)가 관리한다.

이 문서가 **완료 요약·진행 상태·남은 작업·착수 순서의 정본**이다. 상세 설계와 인수 기준은 [문서 지도](README.md)의 담당 문서, 실제 배포 상태는 [서버 운영 안내](SERVER-OPERATIONS.md), CLI 후보·게시 상태는 [CLI 릴리스](CLI-RELEASE.md)가 관리한다.

## 전체 작업 현황

miy.works 공유 플랫폼 0.20.0에 앱 탭 유지(계정당 프레임 10개), 관리자 승인 회원가입, CLI·Codex·Claude Code 통합 설치를 반영했다. 문서·화이트보드 0.3.0과 메신저 0.2.0은 앱 dev에서 확인했다. [반영과 검증 기록](releases/miy-works-0.20.0-2026-11-24-deployment.json)

**G4·기본 공용 UI·앱 소유 ACL/공유·작은 첨부의 첫 구현과 격리 검증을 완료했다.** 대표 프로젝트·업무 앱에서 함께 사용하는 예제를 제공한다. 이후 셸·개인 설정·공용 UI와 앱 연계를 miy.works 개발 서버에 반영했다. 공식 앱별 출시와 실사용 인수 상태는 아래 작업표에서 확인한다.

| 상태 | 이 문서에서 뜻하는 것 |
| --- | --- |
| 완료 | 지정한 구현·반영·게시 범위를 끝냄. 전체 제품이나 모든 환경 인수의 완료는 아님 |
| 일부 구현 | 재사용할 기반은 있지만 해당 기능의 완료 조건을 채우지 못함 |
| 진행 중 | 실제 착수한 구현과 진행 근거가 있음. 조사 완료나 일부 기반만으로 표시하지 않음 |
| 미착수 | 설계·대상은 있으나 해당 후속 구현을 시작하지 않음 |
| 검증·반영 대기 | 코드·후보가 있어도 해당 실행·환경·반영 증거가 없음 |
| 결정 대기 | 채택·범위·외부 접속 정책을 정해야 함. 자동으로 필수 기능에 포함하지 않음 |

**공통 기능 첫 구현과 파일럿 준비 보완을 2026-11-15 개발 서버에 반영했다.** CLI/번들 0.10.0·Rust SDK 0.4.0·UI 1.1.0·schema 23을 게시·반영했고, 게시 CLI로 새 앱 하나를 만들어 서버 빌드·dev 배포·프레임 표시까지 확인했다([반영 기록](releases/pilot-0.10.0-2026-11-15-deployment.json)). **대기:** 배포된 프레임·preview에서 디렉터리 선택/공유/첨부를 함께 쓰는 전체 경로, 새로 등록한 실제 사용자의 로그인, Windows·AI 에이전트 인수. Core HTTP·실제 PostgreSQL·브라우저 검사는 각각 분리한 환경에서 수행했으며 하나의 실제 서버 전체 인수로 합산하지 않는다([검증 기록](releases/common-components-2026-11-14-validation.json), [리뷰 후속 기록](releases/common-components-2026-11-15-review-fixes.json)). 파일럿 준비 점검에서 찾은 공백과 그 보완(앱 DB 권한 경계, 이미지 계약 추출 제한, migration 시간 한도, 사용자 등록, 새 서버 seed·프레임 런타임)은 [점검 기록](releases/pilot-readiness-2026-11-15-validation.json)과 [보완 기록](releases/pilot-improvements-2026-11-15-validation.json)에 있다.

**후속 보완의 구현·격리 검증을 완료했다.** 앱 DB의 로그인·대상 DB 고정, 프록시 복구 재시도, 파일럿 실패 정리와 결과 식별자를 보완했다. 이 수정은 miy.works의 2026-11-16 초기 설치와 dwdcc.kr의 [2026-11-17 반영](releases/dwdcc-0.12.1-2026-11-17-deployment.json)에 포함했다. 새 복구 도구·파일럿 검사 v2의 실제 실행은 별도로 남는다. 원래 검증은 [후속 검증 기록](releases/pilot-review-fixes-2026-11-15-validation.json)에서 배포된 0.10.0과 구분한다.

**서버 배포를 서버 빌드 산출물로 한정하는 변경의 구현·격리 검증을 완료했다(2026-11-16, CLI/번들 0.11.0 후보).** 로컬 배포용 빌드와 이미지 업로드를 제거해 `app build`는 항상 서버에서 검사·빌드하고, 서버는 그 앱의 성공한 서버 빌드가 만든 이미지만 dev에 배포하고 prod로 승격한다. 앱 컨테이너의 외부 통신은 플랫폼이 제한하지 않고 네트워크·호스트 방화벽이 담당하는 것으로 확정했다. miy.works에는 서버·worker와 CLI 0.11.0을 반영하고 한 줄 설치로 게시했다([반영 기록](releases/online-cli-2026-11-16-deployment.json)). 최초 격리 결과는 [검증 기록](releases/server-build-only-2026-11-16-validation.json)에 보존한다.

**miy.works를 Core·CLI 0.14.0으로 올렸다(2026-11-21, `e5ee24f`).** 여러 CLI·MCP 호출이 동시에 실행될 때 로그인 갱신 중인 다른 프로세스 때문에 `reauthentication_required`로 끝나던 문제와, 재생성된 DB 컨테이너에 실행 중인 앱이 닿지 못하던 문제를 고쳤다. 두 문제 모두 재현하는 회귀 검사를 추가했다(146개 관찰). 초대로 만든 개발자와 게시 CLI로 베타 개발자 경로를 다시 확인했다. [반영 기록](releases/miy-works-0.14.0-2026-11-21-deployment.json)

**계정 발급과 로그인 보호를 구현해 miy.works에 반영했다(2026-11-20, 서버 전용 `86f8c53`, schema 26).** 관리자가 콘솔에서 1회용 초대 링크와 비밀번호 재설정 링크를 만들고, 받은 사람이 직접 계정을 만들거나 비밀번호를 정한다. 로그인한 사람은 화면에서 스스로 비밀번호를 바꾼다. 로그인 잠금·비밀번호 정책·한국어 로그인 화면을 기본 설정으로 넣었고, 실제 Keycloak과 브라우저로 새 사람의 가입→포털 로그인→재설정→본인 변경을 확인했다. 메일 서버·공개 가입은 범위 밖이다. [사용 계약](ACCOUNTS.md) · [검증 기록](releases/account-links-2026-11-20-validation.json) · [반영 기록](releases/account-links-2026-11-20-deployment.json). 같은 날 miy.works를 0.13.0으로 맞추고([기록](releases/miy-works-0.13.0-2026-11-20-deployment.json)) 매일 무중단 백업을 켰다.

## 완료한 작업

**공식 업무 앱 공급 기반(V1-F6)을 dwdcc.kr에 배포했다.** Core·CLI 0.13.0과 schema 25에서 기본 제공·공식 업무·조직 제작 앱을 분류하고, 공식 소스를 검증한 버전만 설치·갱신한다. 플래너·메신저는 기본 제품, PMS·PLM은 선택 제품으로 등록했다. 당시 네 제품은 분류만 등록했다. 이후의 출시·설치 상태는 아래 공식 앱 포팅 항목에서 관리한다. [0.13.0 배포 기록](releases/dwdcc-0.13.0-2026-11-18-deployment.json) · [제품 계약](PRD.md#업무-앱의-공급과-설치) · [설치·갱신](RUNNING.md#공식-앱-공급과-설치) · [격리 검증 기록](releases/official-app-catalog-2026-11-18-validation.json)

같은 버전에 거절된 빌드 재시도, 릴리스 ID를 이용한 담당자 인계, 승격 실패 시 마지막 정상 릴리스 보존을 반영했다. 코어 갱신은 선택한 카탈로그를 백업 사본에 먼저 적용하고, 공식 제품을 사용 중인 DB에는 보호 계약을 지원하는 서버만 연결한다. [리뷰 보완과 검증 범위](releases/official-app-catalog-recovery-2026-11-18-validation.json)

## 미해결 호환성 관찰

Docker 28 classic image store의 native `docker save` 결과를 서버가 가져오지 못하던 관찰은 **해결이 아니라 대상에서 빠졌다.** 0.11.0 후보부터 서버는 이미지 archive를 받지 않고 자신이 빌드한 이미지만 실행하므로 앱 배포에는 해당 경로가 없다. dwdcc.kr은 0.12.1 반영 시점부터 서버 빌드 방식으로 운영한다. 예전 Docker archive 관찰을 해결 완료로 바꾸지는 않는다. [회귀 환경과 한계](../scripts/runtime-regression/README.md)를 따른다.
