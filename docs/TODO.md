# UI/UX 개선 기록

이번 작업은 운영 0.6.3 소스의 main 통합, Windows 설치기 구현·검증 절차 준비, Codex·Claude 각각의 새 앱·새 세션 개발 인수를 순서대로 진행한다. 코어 동작을 막는 문제를 우선 수정하고 아래 화면·사용성 개선은 후속 작업으로 남긴다. 현재 상태와 절차는 [추진 계획](PLAN.md)과 [핵심 흐름 사용자 테스트](CORE-TESTING.md)를 따른다.

사용자 CLI의 우선 개선·인수 대상은 Windows 11 x64다. 기본 경로는 네이티브 로컬 개발과 서버 원격 빌드이며 Docker Desktop 설치를 요구하지 않는다. PowerShell 5.1/7의 설치·서버 등록·로그인·앱 생성·로컬 개발·개발 배포 결과는 각각 구분한다. Windows GUI 설치기 구현과 사용법은 [설치 안내](WINDOWS-INSTALLER.md)에 기록한다. Linux에서도 독립 AI 개발·dev 배포를 확인할 수 있다. macOS 추가 인수와 prod 승격은 이번 작업과 별도로 추적한다.

- Windows GUI 설치기 구현과 새 게시 CI 파일의 버전·source·해시 확인 절차를 준비한다. 2026-11-02 사용자 지시에 따라 실제 Windows 11 검사는 사용자가 추후 수행하며 `NOT_RUN`이다. 실제 인수에서는 일반 사용자 여부를 기록하고 사전 설정·검증용 환경변수가 없는 최초 설치, 갱신, 기존 다른 서버 연결·context 보존, 브라우저 승인, 제거·재설치와 앱 데이터 보존을 확인한다. 사내 HTTP IP 인수는 사용 가능한 별도 환경에서 수행한다. 코드 서명과 조직별 배포 정책 적용은 후속 검토한다.
- Codex·Claude 각각 새 작업 폴더·앱 ID·세션에서 업무 앱 개발 → 서버 원격 빌드 → dev 배포 → 동일 DB·레코드 보존을 인수한다. 각 도구의 인증, 실제 MCP/CLI 호출, 소스 commit·job/release/image, 수동 개입을 구분해 기록한다. Codex와 Claude 인증을 확인했으며 두 도구의 새 개발 인수는 진행 중이다. 이전 Todo 실증이나 연결 검사로 대신하지 않는다.
- HTTP IP에서는 클립보드 API가 제한될 수 있어 설치 명령을 직접 선택·복사하는 안내가 필요하다. 현재 수동 복사 경로를 유지하고 복사 상태 표시를 개선한다.
- 설치 안내에서 기존 활성 연결과 이번 명령의 대상 서버가 다를 때 두 주소와 추가·선택 명령을 더 쉽게 비교하도록 배치한다.
- context 저장 이름 `default`를 미리 정해진 서버 주소로 오해하지 않도록 화면 용어를 검토한다. 실제 서버 주소는 명시적 입력으로만 등록한다.
- 개발 세션 충돌·만료 화면에 세션 소유자, 남은 시간, 중지 후 재실행 절차를 읽기 쉽게 정리한다.
- 개발자 등록 요청과 관리자 승인, 운영 배포 권한 부여의 진행 상태를 연결해서 보여주는 안내를 검토한다.
- 배포 작업의 마지막 표시 단계가 `health_check`여도 앱 상태 검사 이후 서버의 후처리에서 실패할 수 있다. 실제 앱 상태와 작업 실패 위치를 구분해 표시하고, job ID로 진단 기록을 찾는 안내를 개선한다.
- 브라우저 로그인 요청 만료·중복 콜백의 실제 IdP 재현과 복구 화면 안내를 확인한다. 복구 화면은 0.6.3에 구현했으나 실제 IdP 만료·중복 콜백 인수는 남아 있다. 2026-10-28 사용자 테스트에서 로그인 시간 초과 안내 후 새로고침·관리자 로그인 시 오류가 표시됐고, 다시 로그인하자 정상 진입했다. 같은 시간대에 Keycloak의 `expired_code`·`already_logged_in`과 이후 관리자 API 200 응답을 확인했다. 오류 요청 ID: `00cb6859-9481-47ac-8341-78b653627a96`.

## 0.6.3 구현·게시 현황과 남은 인수

현재 운영 서버·게시 CLI는 **0.6.3 / 번들 0.7.1**, artifact source는 `8d7d042`다. main 통합 commit과 운영 배포물의 출처를 구분한다. [검증 행렬](CLI-VALIDATION-MATRIX.md)의 기존 Windows 0.6.2 개발·배포 기록, 0.6.3 파일 다운로드·해시 확인, 11-02 CLI/MCP 연결 기록은 보존하며 새 설치기 실행이나 새 AI 개발 통과로 확대하지 않는다.

- 새 CLI ZIP의 버전·출처·해시를 받는 설치기 빌드/검사와 workflow로 변경했고 0.6.3 배포물을 게시했다. 게시 파일 검사와 사용자의 실제 Windows 설치·갱신·제거 결과를 별도로 기록한다.
- 로컬 Docker가 없거나 Linux 엔진이 아니면 `miy app build --remote`를 텍스트와 구조화 recovery에 안내한다. 명시적 요청 없이 소스를 서버에 업로드하지 않는다.
- CLI 로그인은 만료 시각·남은 시간·원래 context의 새 로그인 명령을 반환한다. 승인 화면은 인증된 서버 메타데이터로 남은 시간을 표시하고, 만료·처리된 요청의 승인 입력을 막으며 새 명령을 안내한다. OAuth 실패는 로그인 쿠키를 지우고 고정된 복구 화면으로 보낸다. 서버 반영과 별도로 실제 IdP 만료·중복 콜백 재현은 미실행으로 남긴다.
- 390px 화면에서 사이드바를 접고 메뉴로 열도록 변경했다. 경로 이동 후 메뉴를 닫고 앱 영역의 폭을 확보한다. 플랫폼 소스 화면 검증과 실제 서버 배포 화면 검증을 구분한다.

실제 Windows·독립 AI 인수에서 발견한 추가 항목은 재현 단계와 화면·CLI 위치를 함께 기록한다. 실행하지 않은 단계는 `NOT_RUN`, 실제 실행 후 실패한 단계는 `FAIL`로 표시하고 실행 증거가 있는 단계만 `PASS`로 변경한다.
