# 플랫폼 영역과 후속 UI 계약

- 기준: 2026-11-09 [사내 앱 실행·관리 경계](APP-BOUNDARIES.md). **회사 통제 앱의 프레임 실행(2026-11-10 채택, 2026-11-12 운영 반영)·prod/dev/console 세 출처 분리 구현과 운영 반영**([dev 포털 배포](releases/dev-portal-2026-11-09-deployment.json), [콘솔 이동](releases/console-hostname-2026-11-09-deployment.json)).
- UI-1~5의 ai-do 기반 이식·후속 리뷰는 [완료 이력](archive/UIUX-MIGRATION-UI1-5.md)에 보존한다. 후속 원본은 miy v1이며 독립 앱의 iframe 방식을 v2의 필수 UI 계약으로 이식하지 않는다.

## 세 영역의 화면 책임

| 영역 | 화면 계약 |
| --- | --- |
| 업무 포털·dev 포털 | 업무 포털은 prod 목록·앱, dev 포털은 권한 있는 사용자의 dev 미리보기·시험 앱을 제공. 각 포털 안에서 통합 라우팅하며 기술 상태·DB·이미지·관리 작업은 콘솔에서 제공 |
| 앱 관리 콘솔 | 담당 앱·환경, 미설치/사용 중지 앱, 릴리스·작업·진단과 개인 CLI 승인. 서버가 제공한 동작별 권한 사용 |
| 플랫폼 관리 | 같은 콘솔 안의 사용자·그룹·권한·등록·설치 승인·감사·공용 자산. Keycloak 로그인은 콘솔 `/identity`에서 제공 |

앱 화면은 독립 빌드한 모듈을 해당 환경의 포털 라우터에 직접 로드하며 iframe을 사용하지 않는다. 현재 범위는 사내망에서 회사가 통제하는 앱이다. prod 포털·dev 포털·관리/CLI 승인/로그인 콘솔은 별도 출처다. IdP는 콘솔에 함께 두고 콘솔에는 앱 모듈·활성 앱 콘텐츠를 제공하지 않는다. 테마·언어·탐색·입력 유실·선택기는 SDK 함수·공용 UI를 확장한다. 상세 세션 용도와 권한은 [경계 설계](APP-BOUNDARIES.md#앱-실행-계약)와 [코어 권한](CORE-PERMISSIONS.md)을 따른다.

단일 IP·사설 CA HTTPS를 지원하고 출처별 호스트명을 권장한다. 세 출처의 포트를 나눌 수 있지만 쿠키 격리로 간주하지 않는다. 관리자·develop 계정도 권한에 맞게 dev 포털에서 앱을 확인한다. prod 업무 입장은 명시적 use/all과 앱 ACL을 따른다. 개발 단계에서는 구 UI·SDK·CLI 호환을 위해 전환 계층을 추가하지 않아도 된다.

**다른 출처로 가는 링크만 새 탭으로 연다.** 포털↔콘솔·prod↔dev 포털 이동, 콘솔의 "포털에서 앱 열기"·앱 경로 안내, 포털의 관리 콘솔·개인 CLI 연결이 해당한다. 포털 안에서 앱을 여는 홈의 앱 열기와 앱 레일은 통합 라우팅을 위해 같은 탭을 유지한다. 2026-11-09 [사용자 결정과 격리 검증](releases/boundary-followup-2026-11-09-validation.json)으로 이 동작을 확정했고, 현재 세 출처 UI는 [dev 포털 배포](releases/dev-portal-2026-11-09-deployment.json)에 반영했다. `↗` 표시와 접근성 안내, `noopener noreferrer`를 사용한다. 새 탭 링크는 원래 화면을 떠나지 않으므로 입력 유실 확인을 띄우지 않는다. 각 영역 내부 메뉴·앱 내부 라우팅·로그인/로그아웃·기존 주소의 자동 이동은 같은 탭을 유지한다.

## 7. 기본 UI 이후 후속 작업의 경계

기존 참조 번호는 유지한다. 아래의 순서는 [추진 계획](PLAN.md#다음-우선-작업)이 정한다.

- **7-1 공용 UI:** v1 UI 원칙·primitive·날짜/공휴일(V1-U1·U4·U5)의 독립 부분은 병행할 수 있다. 테마/언어·SDK 확장(U2·U3·U6)은 유지할 통합 런타임 계약에 맞춰 설계하며 iframe 브리지 교체를 기다리지 않는다. 실제 구현 순서는 PLAN을 따르고 게시 SDK·컴포넌트는 새 불변 버전으로 확장한다.
- **7-2 권한 기반:** 최소 보안 보완 다음에 공통 디렉터리·현재 그룹 확인과 앱 소유 ACL의 공통 SDK·회수·감사 계약을 구현한다. 전역 워크스페이스를 만들지 않는다. PLM 등 독립 업무 앱은 이 공통 기능을 사용하며 서비스 계정·API Invoke·업무 이벤트·대용량 파일은 PLAN의 후속 순서로 진행한다. 전체 PLM 기능을 현재 보안 단계의 완료 조건으로 두지 않는다.
- **7-3 공통 업무 기능:** Storage·파일·알림·편집기·선택 업무 앱. 경계 정리를 대규모 디자인 개편이나 v1 코드 복사의 근거로 삼지 않는다.

## 검증과 상태

동적 앱 추가·통합 라우팅의 인수 요구를 유지한다. 세 출처와 세션 용도·환경별 앱 입장, 콘솔의 device CLI 승인·IdP, 관리/사용 권한, 응답·문자열 방어와 dev/prod UI를 실제 Core·브라우저로 확인한다. [dev 포털 격리 검증](releases/dev-portal-2026-11-09-validation.json)은 실제 Core UI 7개·전체 스택 6개를 통과했고, 운영의 세 출처 SSO·CLI/MCP 연결은 [콘솔 이동 기록](releases/console-hostname-2026-11-09-deployment.json)에서 구분한다. 현재 배포에서 실제 로그인 사용자가 dev/prod 앱을 각각 여는 검사, 실제 Windows·기존 기기 worker 정리·인쇄 전체 인수는 NOT_RUN이다. 같은 포털의 앱을 강제로 격리했다는 판정은 하지 않는다. 과거 PASS를 새 인수로 옮기지 않으며 운영 dist·Windows 사용자 수행 원칙을 유지한다.
