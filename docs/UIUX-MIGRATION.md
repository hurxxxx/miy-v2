# 플랫폼 영역과 후속 UI 계약

- 기준: 2026-11-07 [사내 운영 경계](APP-BOUNDARIES.md). **회사 통제 앱의 iframe 없는 통합 UI·두 출처 분리·최소 경계 구현과 운영 반영**([배포 기록](releases/internal-minimum-security-2026-11-07-deployment.json)).
- UI-1~5의 ai-do 기반 이식·후속 리뷰는 [완료 이력](archive/UIUX-MIGRATION-UI1-5.md)에 보존한다. 후속 원본은 miy v1이며 독립 앱의 iframe 방식을 v2의 필수 UI 계약으로 이식하지 않는다.

## 세 영역의 화면 책임

| 영역 | 화면 계약 |
| --- | --- |
| 업무 포털 | prod 기본 업무 목록과 사용자 설정, 권한 있는 사용자의 dev 미리보기를 같은 포털에서 제공. 기술 상태·DB·이미지·관리 작업은 콘솔로 이동 |
| 앱 관리 콘솔 | 담당 앱·환경, 미설치/사용 중지 앱, 릴리스·작업·진단과 개인 CLI 승인. 서버가 제공한 동작별 권한 사용 |
| 플랫폼 관리 | 같은 콘솔 안의 사용자·그룹·권한·등록·설치 승인·감사·공용 자산. Keycloak 로그인은 콘솔 `/identity`에서 제공 |

앱 화면은 독립 빌드한 모듈을 포털 라우터에 직접 로드하며 iframe을 사용하지 않는다. 현재 범위는 사내망에서 회사가 통제하는 앱이다. 포털은 dev/prod를 함께 제공하고 콘솔은 관리·CLI 승인·로그인을 담당하는 두 출처로 나눈다. 별도 IdP/dev 포털은 만들지 않으며 콘솔에는 앱 모듈·활성 앱 콘텐츠를 제공하지 않는다. 테마·언어·탐색·입력 유실·선택기는 기존 SDK 함수·공용 UI를 확장한다. 상세 세션 용도와 권한은 [경계 설계](APP-BOUNDARIES.md#앱-실행-계약)와 [코어 권한](CORE-PERMISSIONS.md)을 따른다.

단일 IP·사설 CA HTTPS로 PoC와 운영을 지원하고 도메인은 권장한다. 포털/콘솔의 포트를 나눌 수 있지만 쿠키 격리로 간주하지 않는다. 관리자·develop 계정도 권한에 맞게 포털에서 dev 앱을 확인하며 경계 적용 후 계정 종류에 따른 일괄 앱 금지를 두지 않는다. prod 업무 입장은 명시적 use/all과 앱 ACL을 따른다.

**다른 출처로 가는 링크만 새 탭으로 연다.** 포털↔콘솔 이동, 콘솔의 "포털에서 앱 열기"·앱 경로 안내, 포털의 관리 콘솔·개인 CLI 연결이 해당한다. 포털 안에서 앱을 여는 홈의 앱 열기와 앱 레일은 통합 라우팅을 위해 같은 탭을 유지한다(2026-11-09 사용자 결정으로 `f5210d1`의 앱 새 탭을 되돌림). `↗` 표시와 접근성 안내를 제공하고 `noopener noreferrer`로 새 탭의 opener 연결을 끊는다. 원래 화면을 떠나지 않으므로 이 링크에는 입력 유실 확인을 띄우지 않는다. 각 영역 내부 메뉴·앱 내부 라우팅·로그인/로그아웃·기존 승인 주소의 자동 이동은 같은 탭을 유지한다. 이 새 탭 동작은 [격리 웹 검증](releases/new-tab-navigation-2026-11-09-validation.json)을 거쳐 2026-11-09 UI `f5210d1`로 [운영 배포](releases/new-tab-navigation-2026-11-09-deployment.json)했다.

## 7. 기본 UI 이후 후속 작업의 경계

기존 참조 번호는 유지한다. 아래의 순서는 [추진 계획](PLAN.md#다음-우선-작업)이 정한다.

- **7-1 공용 UI:** v1 UI 원칙·primitive·날짜/공휴일(V1-U1·U4·U5)의 독립 부분은 병행할 수 있다. 테마/언어·SDK 확장(U2·U3·U6)은 유지할 통합 런타임 계약에 맞춰 설계하며 iframe 브리지 교체를 기다리지 않는다. 실제 구현 순서는 PLAN을 따르고 게시 SDK·컴포넌트는 새 불변 버전으로 확장한다.
- **7-2 권한 기반:** 최소 보안 보완 다음에 공통 디렉터리·현재 그룹 확인과 앱 소유 ACL의 공통 SDK·회수·감사 계약을 구현한다. 전역 워크스페이스를 만들지 않는다. PLM 등 독립 업무 앱은 이 공통 기능을 사용하며 서비스 계정·API Invoke·업무 이벤트·대용량 파일은 PLAN의 후속 순서로 진행한다. 전체 PLM 기능을 현재 보안 단계의 완료 조건으로 두지 않는다.
- **7-3 공통 업무 기능:** Storage·파일·알림·편집기·선택 업무 앱. 경계 정리를 대규모 디자인 개편이나 v1 코드 복사의 근거로 삼지 않는다.

## 검증과 상태

동적 앱 추가·통합 라우팅의 기존 인수 요구를 유지한다. 신규 최소 인수는 두 출처와 세션 용도, 콘솔의 CLI 승인·IdP, 관리/사용 권한, 안전한 문자열·응답 헤더·API 탐색 방어와 정상 dev/prod UI를 실제 core·브라우저로 확인한다. 상세 결과는 [경계 인수](APP-BOUNDARIES.md#경계-인수)의 실제 실행 범위를 따른다. 최소 경계 구현 당시의 격리 Core UI 7개·전체 스택 6개 검사는 PASS이며, 운영 서버·UI `a4ad370` 반영과 이후 확인은 [배포 기록](releases/internal-minimum-security-2026-11-07-deployment.json)에서 구분한다. 위 새 탭 변경의 격리 Core·전체 스택 재실행, 실제 Windows, 기존 기기의 worker 정리와 인쇄 전체 인수는 NOT_RUN이다. 같은 페이지의 앱을 강제로 격리했다는 판정은 하지 않는다. 과거 PASS를 새 인수로 옮기지 않고 운영 dist·Windows 사용자 수행 원칙을 유지한다.
