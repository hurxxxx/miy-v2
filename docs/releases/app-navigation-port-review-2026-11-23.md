# 포팅 앱 내비게이션 계약 검증

대조 기준은 miy-v2 원격 `main`의 `fc880b1`이다. 첫 이식의 AI-DO 기준은 `0002af062`이며 이번 공동편집 의존성은 원본 작업본 `21f3937e2`에서 다시 확인했다. 7개 앱의 SDK 0.13.0 이행은 `de38c8a`에서 `ec0129e`까지 반영돼 있었다. 이번에는 앱 코드가 [내비게이션과 앱 수명주기](../../templates/rust-react/docs/CONTRACT.md#navigation-and-application-lifecycle)를 실제로 따르는지 확인했다.

## 런처에 표시되는 앱

[0.18.0 배포 기록](miy-works-0.18.0-2026-11-23-deployment.json)에는 miy.works의 메신저·PMS 0.1.1이 각각 dev·prod에 설치돼 있다. [공식 카탈로그](../../registry/apps/catalog.json)의 플래너·게시판·드라이브·문서·화이트보드는 출시 목록이 비어 있다. 포털은 소스나 카탈로그 전체가 아니라 현재 환경에서 현재 사용자가 열 수 있는 설치를 조회한다. 앱바에 고정한 경우 전체 런처에서 나머지 접근 가능 앱을 확인할 수 있다.

## 적용 범위

| 앱 | 수정·검증 항목 |
| --- | --- |
| 플래너 | 열린 일정의 언어가 바뀌어도 세션 API를 다시 호출하거나 편집 초안을 덮어쓰지 않는다. |
| 메신저 | 대화별 첨부 초안과 진행 중 업로드를 원래 대화에 연결한다. 뒤로 가서 같은 메시지 링크를 열 때 다시 초점을 맞추고, 늦게 도착한 이전 페이지 요청이 로딩을 남기지 않는다. |
| PMS | 태스크로 연결된 주소와 내부 질의 변경이 목록 전체를 반복해서 읽지 않는다. 선택 목록과 늦은 요청을 분리하고, 공간 순서 대화상자의 미저장·저장 중 상태를 플랫폼에 전달한다. |
| 게시판 | 같은 채널에서 목록 → 글 상세 → 뒤로 가기 또는 언어 변경 시 목록 페이지를 유지한다. 목록 조회와 글 상세 조회의 요청 범위를 분리했다. |
| 드라이브 | 폴더 트리·검색을 안정적인 SDK 메서드와 해당 경로에 결합한다. 늦은 조회·삭제 응답과 공간별 초안을 분리하고 뒤로 가기 때 주소의 검색 상태를 복구한다. 업로드는 SDK 바이트 진행률을 표시하고 서버가 확정한 오프셋을 기준으로 재개한다. |

## 문서·화이트보드 별도 과제

- [문서 포팅 기록](../../apps/docs/docs/PORTING.md)의 BlockNote 0.52.1과 [화이트보드 포팅 기록](../../apps/whiteboard/docs/PORTING.md)의 Excalidraw 0.18.1은 앱 번들에 이미 들어 있다. 단독 편집·리비전 저장은 각 앱 백엔드의 기존 기능이다. 화이트보드 글꼴은 설치 빌드가 자체 호스팅하며, 두 앱의 실제 설치 프레임에서 편집·저장·충돌·파일·내보내기 인수가 남아 있다.
- 원본의 공동편집에는 Yjs 상태를 처리하는 WebSocket 방과 인스턴스 간 Redis 중계가 있다. 문서는 BlockNote 블록과 Yjs 사이 변환에 Node 스크립트도 실행한다. 현재 miy 프레임의 실시간 연결 계약과 앱 ACL로 단일 인스턴스에서 재연결·동시 저장·권한 회수를 먼저 확인하고, 협업 프로세스·Node 런타임·Redis를 어떤 형태로 운영할지 정한다. 공동편집 작업과 인스턴스 구성 변경은 `NOT_RUN`이다.

## 실행 기록

`miy app check --harness-only`와 `miy app fmt`는 프로젝트 안에서 실행했다. 전체 `miy app check`의 첫 시도는 서버 포함 로컬 CLI와 기존 앱의 생성 안내가 달라 `cli_guidance_version_mismatch`로 끝났다. 임시 작업본에서 호환 번들을 확인하고 `miy app setup`으로 안내를 생성한 뒤 전체 검사를 재실행했다. 저장소의 SDK와 생성 안내는 변경하지 않았다. 하네스의 스토리지 복구 권고는 실제 전송·권한 인수 항목으로 남긴다.

| 앱 | `pnpm test` | 임시 작업본 전체 `miy app check` |
| --- | --- | --- |
| 플래너 | PASS 140 | PASS |
| 메신저 | PASS 210 | PASS |
| PMS | PASS 552 | PASS |
| 게시판 | PASS 71 | PASS |
| 드라이브 | PASS 87 | PASS |

`python3 scripts/test-official-apps.py`는 12건 통과했다. 실제 계정으로 포털·preview·설치 프레임을 잇는 이번 변경의 검증, 앱 DB를 통한 인수와 서버 반영은 `NOT_RUN`이다.
