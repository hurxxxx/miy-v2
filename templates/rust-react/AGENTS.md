# miy application development

This is an independent Rust + React application. Keep application source edits in this directory; the CLI manages its own user-scoped contexts and credentials.
Before CLI work, read the project `miy-cli` skill: [Codex](.agents/skills/miy-cli/SKILL.md) or [Claude Code](.claude/skills/miy-cli/SKILL.md). Use [docs/CLI-REFERENCE.md](docs/CLI-REFERENCE.md) for the workflow and full command reference matching the installed CLI. These local instructions are available before MCP login or connection; use `miy describe` and then `miy describe --command "GROUP ACTION"` to inspect only the needed command. The `miy-app` skill covers application implementation and SDK contracts.
After a global CLI update, run `miy app setup` inside this project when the SDK bundle matches, or explicitly use `miy app upgrade` when it differs; then reopen the agent session. Do not hand-edit generated CLI guidance or its `miy.cli.json` lock.
Read docs/CONTRACT.md and query miy_app MCP get_contract, get_cli_help and search_api before coding. The MCP is configured for plain Codex and Claude Code in this project; approve the client's project trust prompt and run `.miy-tools/miy auth login` if authentication is missing. Select the intended context first. Noninteractive login returns public instructions; approve the URL/code and use `auth wait LOGIN_ID`. Never inspect or print credential storage.
Backend business code is src/; React entry is web/src/AppRoot.tsx; SQL migrations are migrations/.
The local sdk/ directory is a versioned platform development bundle. Do not modify SDKs, the Dockerfile, CLI executable, or contract version to bypass checks.
Use `miy_app_sdk::Identity` from Axum Extension for the verified caller; never trust a user ID or admin flag from a request body.
Use `runtime.api()` and `runtime.navigate()` in the UI. No iframe, hardcoded host URLs, or credentials in code.
Use the app DB only. Do not connect to the core DB or another app DB. Never run migrations in the application process; the platform runner applies them.
Do not inspect the platform repository, user secrets, Docker socket, or other projects. Use the CLI for local testing and deployment when the user requests those actions. Test deployment uses `app deploy`; production requires an accepted release and `miy --context CONTEXT --app APP --yes app promote --environment prod --release ID` with separate deploy permission and the user’s authorization. Do not treat permission to develop as permission to publish to production.
Use `.miy-tools/miy describe --command "app check"` or command `--help`; use the `.exe` path on Windows. Run `.miy-tools/miy app fmt` to format only your application, then `.miy-tools/miy app check` before declaring completion. The CLI checks bundle integrity, SQL migration rules, Rust formatting/tests, frozen dependencies, TypeScript, the UI build and Federation assets. Do not weaken checks or modify miy.bundle.json. If a check fails in a protected file, report the bundle defect instead of changing the SDK.
The CLI check does not prove live DB migration correctness or browser integration; those require platform acceptance tests. Record exact commands and failures in your completion report.
Preserve existing migrations; add new numbered transactional SQL files. Document endpoints and behavior in README.md.

Register the intended server with `miy context init` when none is configured; the CLI has no default IP/domain. An offline app init leaves the project unbound until a server is explicitly registered/selected. Register this app and obtain administrator approval before `.miy-tools/miy app dev`. The default preview uses the server development DB through a managed tunnel, and later development deployment reuses exactly that DB and its rows. Only explicit `app dev --runtime docker --database local` uses a separate local DB. Never replace this with a mock identity or a direct core DB connection. Schema changes can stop a deployed development app; preserve applied migrations. Stop the local session with `app dev-stop` before a new deployment; increment manifest version, commit, build, deploy, then inspect `app status` and verify the browser. Record actual test results before `app accept --note ...`. Production uses a separate DB without copying development data.

Public UI components are distributed independently of the CLI. After login run `component sync` to install defaults or restore exact locked releases. Query MCP `list_components` / `get_component` for current usage; use `component add NAME` or `component update NAME --version X.Y.Z` explicitly. Import from `@miy/components/NAME`; `@miy/ui` remains the basic UI alias. Never hand-edit `platform-components/` or its lock. Commit the entire directory. Publishing a new registry version does not update an app; review, test and redeploy explicitly.

For forms or in-flight actions, register `runtime.registerNavigationGuard` in an effect with cleanup (see docs/CONTRACT.md); test app links, platform menus, browser history and refresh. Do not infer dirty state automatically or add duplicate confirms. Use docs/ACCEPTANCE.md to record actual integration boundaries and not_run items with `app accept --report`. Stop a completed local preview with app dev-stop and verify it can restart. Platform display names are administrator-managed via app rename, independently of manifest names.

Use `--output json` for automation and follow structured error recovery arguments. Save request/job IDs; `job resume ID` recovers the same request, while `job retry ID` is only for a typed retryable failed job after fresh checks. Never turn a network failure into a new deployment automatically. Prod operations and app removal require explicit context/app/environment and confirmation; dry-run skips changes and confirmation.

Local development defaults to native Rust plus the built React preview and an in-process tunnel to the server dev DB. Docker Desktop, WSL and local PostgreSQL are not needed for `app dev` or `doctor --for develop`. Explicit `--runtime docker` selects the container workflow. Image build/deployment still require a Linux Docker engine; native preview is not a releasable Linux image.
